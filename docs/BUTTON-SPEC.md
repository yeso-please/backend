# 버튼 단위 인터랙션 명세 (v0.1, legacy)

> **구현 기준 아님:** 현재 MVP 흐름은 [docs/mvp/flow.md](mvp/flow.md), API는 [docs/mvp/api.md](mvp/api.md)를 따른다.

> "무슨 버튼을 누르면 무슨 일이 일어나는가"만 다룬다. 기능 규칙은 [FEATURE-SPEC.md](FEATURE-SPEC.md),
> API 세부는 [API-DESIGN-DRAFT.md](API-DESIGN-DRAFT.md) 참고. v1 플로우(로그인은 선택, 저장 시점에만 필수)만 다룬다.
>
> 데모(`yeso-please/demo`)의 실제 UI를 먼저 확인해서 검증된 패턴은 그대로 가져왔다 — 특히
> "게스트로 코스를 만들다가 저장 시점에 로그인 유도 → 로그인 후 자동 저장" 패턴은 데모
> `course.js`(`sessionStorage['courseDraft']` + 복귀 후 복원)에 이미 구현돼 있던 것과 동일한
> 아이디어다(DEMO-REFERENCE.md 참고). 지역 추첨도 데모처럼 **"다시 뽑기" 전용 버튼을 따로 안 두고
> 같은 버튼을 다시 누르면 재추첨**되는 방식을 따른다.

## 화면 구성 (v1)

```
[진입] → [온보딩] → [지역 추첨] → [코스 슬롯] → (저장 시점에만) [로그인/가입] → [완료]
```

| **"건너뛰기"** | 언제든 | 응답 없이 다음 화면으로 | 없음 | §3로 이동, `tasteVector` 없는 상태(취향 미반영 추천으로 폴백, FEATURE-SPEC §3) |

## 3. 지역 추첨 화면 (슬롯머신)

| 버튼 | 조건 | 로컬 동작 | API 호출 | 성공 후 |
|---|---|---|---|---|
| **"뽑기!" / "여행지 뽑기"** | 항상 | 추첨 애니메이션 시작(연출용, 응답 오기 전까지 로딩) | `POST /api/discovery/draw` `{mode, situation, tasteVector?}` (게스트만 `tasteVector` 포함) | 애니메이션 종료 후 지역명(도+시군구) 표시 |
| **동일 버튼 재클릭("다시 뽑기")** | 결과가 마음에 안 들 때 | 위와 동일 — **별도 리롤 버튼을 두지 않는다**(데모 패턴 계승) | 위와 동일 | 새 지역으로 갱신 |
| **모드 토글**("완전 랜덤" ↔ "내 취향 반영") | `tasteVector` 또는 로그인 상태가 있을 때만 노출 | 다음 뽑기 요청의 `mode` 값을 바꿈 | 없음(다음 뽑기 때 반영) | UI 토글 상태만 변경 |
| **"이 지역으로 코스 만들기"** | 지역이 뽑힌 후 | 선택된 `regionId`를 들고 다음 화면으로 | 없음(다음 화면 진입 시 §4의 draft 호출) | §4로 이동 |

## 4. 코스 슬롯 화면

| 버튼 | 조건 | 로컬 동작 | API 호출 | 성공 후 |
|---|---|---|---|---|
| *(화면 진입 시 자동)* | §3에서 넘어온 직후 1회 | 로딩 표시 | `POST /api/courses/draft` `{regionId, transport, origin, situation, stopCount, tasteVector?}` | 슬롯 카드 N개 렌더링(모두 `locked:false`) |
| **하트/찜 아이콘**(슬롯 카드별) | 슬롯 표시 중 | 해당 슬롯의 `locked` 토글(로컬 상태만) | 없음 | 카드에 잠금 표시(예: 테두리 강조) |
| **"다시 뽑기"** | 잠기지 않은 슬롯이 1개 이상일 때 | 현재 전체 슬롯 상태(잠금 포함) 전송 | `POST /api/courses/draft/reroll` `{regionId, transport, origin, situation, stops:[{attractionId,locked}], tasteVector?}` | 잠긴 슬롯은 그대로, 나머지만 새 카드로 교체. 후보 소진 시(`exhausted:true`) "더 뽑을 곳이 없어요" 안내 |
| **"+ 장소 추가"** | 항상 | 슬롯 개수 +1 요청 준비 | `PATCH /api/courses/draft/stops` (개수 변경) | 새 슬롯 1개 추가(추천으로 채워짐) |
| **슬롯 카드의 "삭제(×)"** | 슬롯 2개 이상일 때 | 로컬에서 즉시 제거(카드 사라짐) — 서버엔 다음 리롤/저장 요청에 자연히 반영(별도 API 호출 없음, stateless 설계) | 없음(다음 상호작용에 위임) | 카드 제거, 남은 슬롯으로 재배치 |
| **"저장하기"** | 슬롯 1개 이상 | 로그인 여부 확인 | 로그인 상태: `POST /api/courses` `{regionId, transport, origin, stops}` 바로 호출. **게스트 상태: API 호출 전에 현재 슬롯 상태를 `localStorage['courseDraft']`에 저장하고 §5(로그인/가입 화면)로 이동** | 로그인 상태: §6 완료 화면. 게스트: §5로 이동 |

## 5. 로그인/가입 화면 (저장 시점에 진입한 경우)

| 버튼 | 조건 | 로컬 동작 | API 호출 | 성공 후 |
|---|---|---|---|---|
| **"로그인"** | `localStorage['courseDraft']`가 있는 상태로 진입 | — | `POST /api/auth/login` | 성공 시 `courseDraft` 존재 확인 → 있으면 **자동으로** `POST /api/courses`로 이어서 호출(사용자가 버튼을 또 누를 필요 없음) → §6 |
| **"카카오로 계속하기" / "구글로 계속하기"** | 위와 동일 | 소셜 인가 화면으로 리다이렉트 | 콜백 후 `POST /api/auth/social/{provider}` | 위와 동일 — 성공 시 `courseDraft` 자동 전송 → §6 |
| **"회원가입"** | 위와 동일 | — | `POST /api/auth/signup` | 가입 직후 자동 로그인 처리 → 위와 동일하게 `courseDraft` 자동 전송 → §6 |
| **"나중에 할게요"** | 언제든 | `courseDraft`는 `localStorage`에 남긴 채 이전 화면(§4)으로 복귀 | 없음 | §4로 복귀, 슬롯 상태 그대로 유지 |

## 게스트 → 로그인 전환 시 주의점 (구현 시 반드시 지킬 것)

- `courseDraft`를 `localStorage`에 쓰는 시점은 **"저장하기" 버튼을 눌렀을 때만**이다. 슬롯을 만지작거리는 중에는
  매번 쓰지 않는다(불필요한 쓰기, 그리고 로그인 화면을 거치지 않고 이탈하면 남은 `courseDraft`가 다음 방문 때
  혼란을 줄 수 있음 — "완료 화면"에서 명시적으로 지운다).
- 로그인 성공 후 `courseDraft` 자동 전송은 **1회만** 일어나야 한다 — 전송 성공 즉시 `localStorage`에서 제거해서
  새로고침으로 인한 중복 저장을 막는다.
- 소셜 로그인은 리다이렉트가 껴서 `localStorage`가 아니라 페이지 이동을 거치므로, `courseDraft`가 도메인 내
  `localStorage`에 남아있다는 전제가 깨지지 않게 콜백 처리도 **같은 오리진**에서 이뤄져야 한다(별도 서브도메인
  콜백 페이지를 쓰지 않는다).
