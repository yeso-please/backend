# TriPin 제품 정책

무엇을 왜 만드는지 정하는 문서다. 호출 가능한 API 계약(경로·필드·상태 코드·오류 코드)은 [`api/`](api/README.md), 추천·코스 계산 방식은 [추천 설계](design/recommendation.md)가 기준이다. 정책을 바꾸면 맨 아래 [결정 기록](#결정-기록)에 한 줄 남긴다.

## 사용자 흐름

```text
회원가입·로그인 → 최초 설문(여행 성향·일정 밀도) → 캘린더에서 시작·종료일 선택
(내가 만들었거나 참여 중인 여행 날짜는 선택 불가) → 여행 생성
→ 친구 초대(초대 링크 또는 친구 목록) → 친구는 로그인·설문 후 수락
→ 지역 정하기(랜덤·조건·지도에서 직접 선택) → 지역 카드
→ 코스 생성(최초는 생성자, 재생성은 참여자 누구나 · 요청자의 취향) → 지도에서 관광지 조회·교체·직접 추가 → 식당 추천·검색
→ 참여자 누구나 계속 수정(확정 단계 없음) → 비회원에게는 코스 조회 전용 공유 링크
(추가 기능) 여행이 끝난 뒤 여행기 사진 발행·내 지도 회고
```

## 범위

| 구분 | 내용 |
|---|---|
| MVP | 인증, 설문, 여행·날짜, 초대·친구, 공유, 지역, 코스, 식당 |
| 추가 기능 | 여행기·사진 지도. 항목이 더 늘어날 수 있다 |
| MVP 이후 논의 | 카카오 로그인, 서버의 카카오 메시지 직접 발송, 계정 전환·병합, 리뷰·평점 기반 맛집 순위, 외부 길찾기 확정 정책, 실측 체류시간, 실시간 공동 편집 |

## 참여와 권한

- 여행을 만들고 수정하는 **참여자는 회원**이다. **비회원은 공유 링크로 열람만 하는 뷰어**다(로그인 불필요, 설문·편집 없음).
- 생성자와 참여자는 **동등한 권한**으로 코스 수정, 친구 초대, 탈퇴를 한다.
- 삭제는 없고 **개인 탈퇴**만 있다. 마지막 참여자가 탈퇴하면 여행이 삭제된다.
- 친구 초대는 초대 링크(카카오톡 공유·복사)와 친구 목록에서 바로 초대(받은 초대함, 푸시 없음) 두 가지다. 서버는 카카오 메시지를 보내지 않는다.
- 수락하면 같은 여행이 친구 캘린더에도 보인다. 일정을 복사하지 않는다. 친구의 기존 여행과 날짜가 겹치면 수락할 수 없다.
- 여행 참여자는 최대 8명이다. 가득 차면 수락할 수 없다. 내보내기(강퇴)는 없다.
- 친구 목록에서 보낸 초대는 참여자 누구나 목록으로 보고, 대기 중이면 취소할 수 있다.
- 친구 관계는 회원이 만든 친구 초대 링크를 다른 회원이 수락해 맺는다. 사용자 검색은 없다. 차단은 없고 친구 끊기만 있다.
- 공유 링크는 항상 읽기 전용이며 참여자 누구나 발급·폐기한다. 코스를 만드는 중에도 공유할 수 있다. 토큰은 만료 가능한 난수이고 DB에는 해시만 둔다.
- 공유 링크로 들어온 비회원은 **이미 만들어진 코스의 조회만** 한다. 지역 카드·지도 핀·관광지 상세·후보·식당 API는 회원 전용이며, 공유 화면은 공유 코스 응답 하나로 지도와 항목 카드를 그린다. 공유 세션은 공유 조회 경로(`/api/shared/**`)에서만 인정한다.

## 인증과 설문

- 이메일·비밀번호·닉네임 로컬 가입·로그인만 제공한다. 비밀번호는 BCrypt로 저장한다.
- access token은 응답 body, refresh token은 `HttpOnly; Secure; SameSite=Lax` 쿠키로 준다. 개발 HTTP에서는 Secure만 해제한다. refresh token은 해시 저장·회전한다.
- 최초 로그인 후 설문을 마쳐야 여행을 만들거나 초대를 수락할 수 있다.
- 설문은 여행 MBTI 12문항(각 1/2 선택), 경험 태그 최대 5개, 제외 조건, 좋았던 여행지 0~30개(같은 지역 중복 불가)다. 질문은 버전 관리하며 답변 원본과 계산 결과를 함께 저장한다. 문항은 [API 2장 부록](api/profile.md#부록-설문-문항과-채점-demo-mbti-v1).
- 일정 밀도 `RELAXED`(하루 최대 4곳) 또는 `PACKED`(최대 6곳)를 필수로 고른다. 기본 선호이며 여행마다 바꿀 수 있다.
- 설문 결과는 사용자가 "여행 성향 다시 검사"로 요청할 때만 바뀐다. 과거 제출은 지우지 않고 최신 제출만 추천에 쓴다.

## 여행과 날짜

- 시작일과 `nights`(0~6)를 고른다. `endDate = startDate + nights`, `days = nights + 1`. 당일치기는 0박 1일.
- 여행을 만드는 순간 기간을 차지한다. 내가 만들었거나 참여 중인 여행과 겹치는 날짜는 캘린더와 서버 모두에서 막는다. 우회 수단은 없고, 그 기간을 쓰려면 기존 여행에서 탈퇴한다.
- 만든 뒤 시작·종료일은 바꿀 수 없다. 날짜별 장소와 방문 순서만 바꾼다. **확정 단계는 없다.**
- 종료일이 지난 여행은 읽기 전용이다. 조회·공유·탈퇴만 된다(여행기와 어긋나지 않게 하기 위해서).
- 코스 제목이 없는 여행은 `M월 D일부터 N박 N+1일 여행`(당일치기는 `M월 D일 당일 여행`)으로 부른다. 목록·날짜 겹침 안내·초대 화면이 같은 이름을 쓴다.
- 날짜를 고를 때 그 기간에 추첨 가능한 지역이 없으면 경고한다(막지는 않는다).

## 지역 정하기

- 랜덤 추첨, 조건 추첨(`DISTANCE` 출발지 거리, `MY_TASTE` 요청자 취향), 지도에서 직접 선택으로 정한다.
- 다시 뽑기는 이전 지역을 제외하지 않는다. 같은 지역이 연속으로 나올 수 있다.
- 코스가 있는 여행에서 지역을 다시 정하려면 "코스를 비우고 다시 만들어요" 확인을 거친다. 확인하면 코스가 비워지고, 다음 코스 만들기는 재생성이라 참여자 누구나 한다. 밀도 기본값은 여행에 정해진 밀도, 없으면 요청자의 설문 값이다.

## 지역·관광지 품질

- 추천 가능 관광지는 유효한 지역·좌표·상세 설명·검증된 이미지를 모두 갖춰야 한다. 부족하면 품질 리포트에 남기고 추천에서 뺀다.
- 지역은 승인된 소개문(MVP는 시연 지역만 시드로 승인), 검증된 대표 이미지, 여행 일수에 충분한 추천 가능 관광지(`days × 밀도 상한 + min(days, 3)`)가 있어야 추첨·선택할 수 있다. MVP 시연 지역은 6박 RELAXED를 충족하는 곳으로 고른다.
- 지역 소개문은 역사·특성·대표 여행지를 근거로 합성한 2~4문단이다. LLM을 쓰면 입력 근거와 모델 버전을 저장하고 사람이 승인해야 공개한다.

## 코스와 편집

- 코스는 여행마다 하나이며 서버에 저장하고 버전으로 동시 편집을 막는다. 새로고침해도 유지된다. 버전은 여행마다 하나(`trip_plans.version`)이며 이동수단·출발지 수정, 지역 정하기, 코스 생성·재생성·편집이 모두 같은 버전을 올린다. 재생성해도 계속 증가한다. 코스는 여행 삭제 때만 삭제되고, 지역을 다시 정할 때 확인 후 비워질 수 있다. 이동수단·출발지는 코스가 있어도 바꿀 수 있고 이동시간을 다시 계산한다.
- 최초 코스(코스가 없을 때)는 **생성자가** 자기 취향으로 만든다(생성자가 이미 탈퇴했으면 남은 참여자 누구나). 재생성은 다른 참여자의 편집과 식당 선택을 덮어쓰므로 "다른 참여자의 편집과 식당 선택도 사라집니다"로 확인을 받는다. 되돌리기는 후속이다. 이후 재생성·대체 후보는 **요청한 사람의 취향** 기준이다. 참여자 취향을 평균하지 않는다.
- 코스에는 시각이 없다. 코스는 날짜별 방문 순서 목록이며 관광지와 식사(점심·저녁)를 한 목록에 둔다. 항목마다 체류시간과 앞 관광지에서의 이동시간을 참고용으로만 보여 준다. 가용 시간·시각 검사는 없어서 편집이 "항목이 너무 많음"·"시간 초과"로 실패하지 않는다.
- 하루 관광지는 자동 생성 기준 RELAXED 4곳, PACKED 6곳이 목표다. 체류시간은 유형별 기본값(짧은 장소 60분, 일반 90분, 대형 문화·레포츠 120분), 식사는 60분이며 추정치로 표시한다. 재생성에서 밀도를 바꾸면 여행의 밀도도 바뀌며, 그 밀도에 지역 관광지가 모자라도 거부하지 않고 들어가는 만큼 배치해 경고한다. 하루 1곳도 못 채우는 날이 있을 때만 실패한다. 직접 추가할 때는 개수 제한이 없다. 편집으로 관광지가 0곳인 날도 둘 수 있다.
- 품질 기준에서 빠진 관광지는 일정에 그대로 두고 경고와 교체 제안을 보여 준다. 다른 편집을 막지 않고 공유 화면에도 그대로 보인다.
- 자동 생성은 모든 날에 점심과 저녁을 하나씩 넣는다(첫날·마지막 날·당일치기 포함). 식사는 같은 날 안에서 순서를 옮길 수 있지만(날마다 점심·저녁은 하나씩이라 다른 날로는 못 옮긴다) 삭제·추가는 할 수 없다. 식당을 고르지 않은 식사는 "미정"으로 보인다. 코스 조정은 장소 추가·교체·삭제·이동, 식사 이동과 식당 선택으로 한다.
- 제외 조건은 판정할 수 있는 것만 적용한다. `물놀이`는 관광지 분류로 뺀다. `계단·경사`, `오래 걷기`는 데이터가 없고 `야간 이동`은 코스가 시각을 다루지 않아 MVP에서는 저장만 한다.
- 운영시간·휴무는 원천이 자유 문장이라 MVP에서는 코스 배치에 쓰지 않고 관광지 상세에 원문만 보여 준다.
- 같은 지역의 관광지를 지도 핀으로 보여 준다. 추천 가능 기준(좌표·설명·검증 이미지)을 못 채운 장소도 흐린 핀으로 보이지만 일정에 넣을 수 없다. 상세를 본 뒤 추천 가능 관광지를 일정에 직접 추가할 수 있다. 추가·교체·삭제·이동마다 서버가 이동시간을 다시 계산한다.
- 대체 후보는 코스에 없는 같은 지역 관광지를 유형별로 보여 준다.

## 식당

- 같은 지역의 TourAPI 음식점(`contentTypeId=39`)이 1순위, 농가맛집·모범/향토음식점·착한가격업소처럼 지정 근거가 있는 공공데이터가 보완, 그날 순서에서 식사 앞 마지막 관광지(없으면 지역 중심) 기준 카카오 Local 검색이 fallback이다.
- MVP는 TourAPI 음식점 추천과 카카오 검색만 제공한다. 공공 지정 식당 보완은 추가 기능이다. 추천 결과가 하나도 없으면 화면이 카카오 검색 결과를 자동으로 보여 준다.
- 출처와 추천 근거를 표시한다. 원천이 준 대표 메뉴만 보여 주고, 카카오 결과로 맛·평점·인기·대표 메뉴를 만들지 않는다.
- 고른 식당은 이름·주소·좌표·외부 URL·카테고리·확인된 메뉴·출처를 일정에 스냅샷으로 저장한다.
- 지역 음식·특산물은 출처가 있고 사람이 승인한 항목만 쓴다.

## 외부 서비스와 폴백

- 외부 길찾기는 쓰지 않는다. 이동시간은 직선거리 추정이며 실제 경로라고 표현하지 않는다.
- 취향 임베딩을 쓸 수 없으면 적재된 TourAPI 공식 코스를 기간에 맞게 자르고, 없으면 취향 없는 규칙 코스를 만든다. 둘 다 안 되면 부족 이유를 돌려준다.
- 코스 제목은 MVP에서 규칙 제목 `{지역명}, {대표 테마}를 따라 걷는 {일수}일`이다. LLM 제목은 설정으로 켤 수 있는 선택 기능이며 장소·순서를 정하지 않고 제목만 만든다. 검증된 입력만 쓰고, 실패하면 규칙 제목으로 대신한다.

## 여행기·사진 지도 (추가 기능)

- 여행 종료일이 지난 여행에 참여자마다 여행기 하나. 사진 1~30장, 제목·본문, 만족 태그·점수, 초안·발행 상태.
- 여행기 지도는 내 여행 회고용이다. 핀에는 대표 사진과 코스 제목을 보여 주고, 누르면 여행기를 연다. 전체 지도를 제3자에게 공개하지 않는다.
- 공개 범위는 `PRIVATE`, 친구만 보는 `FRIENDS`, 읽기 전용 링크 `LINK`.
- 사진 위치 공개 정밀도는 기본 `CITY`이며 `EXACT`·`HIDDEN`으로 바꿀 수 있다. EXIF와 원본 파일명은 밖으로 내보내지 않는다.
- 발행된 여행기의 지역·장소 유형·만족 태그와 점수만 낮은 가중치의 취향 신호로 쓴다. 본문·사진 분석·EXIF·열람 수는 쓰지 않으며 사용자가 끌 수 있다.
