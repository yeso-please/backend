# 디렉터리 구조와 의존성

## 디렉터리 구조

```text
com.yeso.backend/
├── auth/
│   ├── domain/
│   ├── application/
│   ├── infrastructure/
│   └── presentation/
├── trip/
├── attraction/
├── profile/
└── shared/
    ├── config/
    ├── exception/
    ├── response/
    └── web/
```

도메인별 패키지를 Bounded Context로 취급합니다. 현재 주요 도메인은 `auth`, `trip`, `attraction`, `profile`입니다.

| 계층 | 책임 |
|---|---|
| `domain` | 엔티티, 값 객체, Enum, 도메인 규칙 |
| `application` | 유스케이스 조율, 트랜잭션, 서비스 |
| `infrastructure` | Repository, JWT, 외부 API 연동 |
| `presentation` | Controller, Request/Response DTO |
| `shared` | 모든 도메인이 사용하는 전역 기반 |

`domain`은 `application`, `infrastructure`, `presentation`을 import하지 않습니다. `shared`도 특정 도메인을 import하지 않습니다. 도메인 간 직접 참조는 꼭 필요한 경우에만 사용하고 순환 의존성을 만들지 않습니다.

기존 평면 구조는 새 기능부터 도메인별 구조로 작성하고, 기존 클래스는 수정할 때 점진적으로 이동합니다.
