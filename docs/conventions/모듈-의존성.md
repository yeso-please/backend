# 디렉터리 구조와 의존성

## 디렉터리 구조

```text
com.yeso.backend/
├── auth/
│   ├── domain/
│   ├── application/
│   ├── infrastructure/
│   └── presentation/
├── trip/
│   ├── domain/
│   ├── application/
│   │   ├── context/
│   │   ├── invite/
│   │   └── course/
│   ├── infrastructure/
│   └── presentation/
│       ├── context/
│       ├── invite/
│       └── course/
├── attraction/
│   ├── domain/
│   ├── application/
│   │   ├── region/
│   │   └── ingestion/
│   ├── infrastructure/
│   └── presentation/
│       ├── region/
│       └── ingestion/
├── profile/
│   ├── domain/
│   ├── application/
│   ├── infrastructure/
│   └── presentation/
└── shared/
    ├── config/
    ├── exception/
    ├── persistence/
    ├── security/
    └── web/
```

도메인별 패키지를 Bounded Context로 취급합니다. 현재 주요 도메인은 `auth`, `trip`, `attraction`, `profile`입니다.

| 계층 | 책임 |
|---|---|
| `domain` | 엔티티, 값 객체, Enum, 도메인 규칙 |
| `application` | 유스케이스 조율, 트랜잭션, 서비스 |
| `infrastructure` | Repository, JWT, 외부 API 연동 |
| `presentation` | Controller, Request/Response DTO |
| `shared` | 모든 도메인이 사용하는 전역 기반 |

`domain`은 `application`, `infrastructure`, `presentation`을 import하지 않습니다. `shared`도 특정 도메인을 import하지 않습니다. 도메인 간 직접 참조는 꼭 필요한 경우에만 사용하고 순환 의존성을 만들지 않습니다.

`trip`과 `attraction`처럼 여러 담당자가 함께 작업하는 모듈은 `application`과 `presentation` 아래를 기능 하위 패키지로 나눕니다. `domain`은 나누지 않고, 하위 패키지끼리 순환 호출을 만들지 않습니다.

평면 `com.yeso.backend.domain`에는 WORK-02에서 제거할 `OnboardingResponse`와 MVP에서 쓰지 않는 `Friendship`, `UserInteraction`만 남아 있습니다. 새 클래스를 이 패키지에 추가하지 않습니다.
