# 코드 컨벤션

Controller·DTO·예외·엔티티 등 코드를 쓸 때 지키는 규칙이다. 패키지 구조와 의존 방향은 [모듈·의존성](모듈-의존성.md).

## API 응답 형식

### 성공

성공 응답은 별도 래퍼 없이 DTO를 반환합니다. HTTP 상태 코드가 성공 여부를 표현하므로 `success` 필드를 중복해서 사용하지 않습니다.

```java
return ResponseEntity.ok(tripService.getTrip(tripId));
```

- 조회·수정: `200 OK`
- 생성: `201 Created`
- 삭제: `204 No Content`

### 실패

모든 실패 응답은 다음 형식을 사용합니다.

```json
{
  "timestamp": "2026-09-21T00:00:00Z",
  "status": 404,
  "code": "TRIP_NOT_FOUND",
  "message": "여행 계획을 찾을 수 없습니다.",
  "path": "/api/trips/1"
}
```

모든 실패는 `timestamp`, `status`, `code`, `message`, `path`를 반환합니다. 검증 실패에는 `fieldErrors` 배열도 반환합니다. 메시지는 사용자에게 보여줄 수 있는 한국어로 작성하며 SQL, 스택 트레이스, 내부 파일 경로는 응답에 포함하지 않습니다.

Service는 `ResponseEntity`를 반환하지 않고 예외를 던집니다. HTTP 변환은 `GlobalExceptionHandler`가 담당합니다.

## 예외 처리

모든 커스텀 예외는 `DomainException`을 상속하는 도메인별 베이스 예외를 거칩니다. `ErrorCode`는 HTTP 상태와 안정적인 기계 판별 코드를 함께 가진다.

```text
RuntimeException
└── DomainException
    ├── AuthException               auth
    ├── OnboardingException         profile (친구 기능이 FriendException 추가)
    ├── TripException               trip
    ├── InviteException             trip 초대·공유 링크
    ├── AttractionException         attraction (지역·관광지 작업이 만든다)
    ├── UnauthenticatedUserException  shared.web
    └── TokenAudienceMismatchException, InvalidExpiresInDaysException  shared.token
```

계약이 그렇게 정하면 도메인 예외가 `COMMON_` 코드를 쓸 수 있다. 예: `TripDatesImmutableException`(`TripException`) → `400 COMMON_INVALID_REQUEST`.

### 오류 코드 이름

`ErrorCode`의 코드 문자열은 프론트가 분기하는 **API 계약**이다. 한번 공개한 코드는 이름을 바꾸지 않는다.

- 새 코드는 `{접두사}_{상황}` 형식의 대문자 스네이크 케이스로 쓴다. 예: `COURSE_INSUFFICIENT_CANDIDATES`, `REGION_CONTENT_NOT_READY`.
- 접두사는 기능 단위다. `COMMON_`(공통), `AUTH_`(인증), `ONBOARDING_`·`FRIEND_`(profile), `TRIP_`·`DRAW_`·`INVITE_`·`SHARE_`·`COURSE_`·`DIARY_`(trip), `REGION_`·`ATTRACTION_`(attraction).
- 코드를 추가할 때는 `docs/api/` 해당 절의 오류 코드 표에도 같은 PR에서 적는다.
- 기존 코드 중 접두사가 없는 것(`INVALID_EXPIRES_IN_DAYS`, `TOKEN_AUDIENCE_MISMATCH`, `ONBOARDING_REQUIRED` 등)은 계약을 깨지 않도록 그대로 둔다.
- 새 코드는 enum 상수 이름과 코드 문자열을 같게 한다(`COURSE_NOT_FOUND(HttpStatus.NOT_FOUND, "COURSE_NOT_FOUND")`). 기존 상수 중 `REGION_NOT_FOUND`는 문자열이 `ONBOARDING_REGION_NOT_FOUND`였으므로 상수를 `ONBOARDING_REGION_NOT_FOUND`로 바꿨고, `REGION_NOT_FOUND`(404)는 attraction이 쓴다.
- `ErrorCode` enum을 BC별로 나누는 작업은 MVP 이후에 한다. 그 전까지는 enum 안을 `// ---- {module} ----` 블록 주석으로 묶는다(`shared: token` 블록에 `INVALID_EXPIRES_IN_DAYS`, `TOKEN_AUDIENCE_MISMATCH`). 새 코드는 **자기 모듈 블록의 끝**에 추가해 병합 충돌을 줄인다.

구체적인 예외의 메시지는 생성자에서 확정합니다.

```java
public class TripNotFoundException extends TripException {
    public TripNotFoundException(Long tripId) {
        super(ErrorCode.TRIP_NOT_FOUND, "여행을 찾을 수 없습니다: " + tripId);
    }
}
```

`shared.exception.GlobalExceptionHandler`가 다음 예외를 공통 응답으로 변환합니다.

- 도메인 예외
- `MethodArgumentNotValidException`
- JSON 파싱 실패
- 파라미터 타입 변환 실패
- 지원하지 않는 HTTP 메서드
- 처리하지 못한 예외

예상하지 못한 예외는 내부 메시지를 노출하지 않고 `error` 레벨로 전체 스택 트레이스를 기록합니다. 비즈니스 예외는 예상된 흐름이므로 `warn`으로 기록합니다.

Security 필터에서 발생하는 인증·인가 예외는 ControllerAdvice가 처리하지 못하므로 `ApiAuthenticationEntryPoint`와 `ApiAccessDeniedHandler`가 동일한 `ApiErrorResponse` 형식을 직접 반환합니다. 구형·별도 오류 응답 DTO를 추가하지 않습니다.

## DTO

DTO는 Java `record`로 작성합니다. Request와 Response는 역할이 다르므로 재사용하지 않습니다.

```java
public record CreateTripRequest(
        @NotNull LocalDate startDate,
        @NotNull Integer nights,
        @NotNull String transport
) {
}

public record TripContextResponse(
        Long id,
        LocalDate startDate,
        long version
) {
}
```

Request에만 검증 어노테이션을 붙인다. Controller는 `@RequestBody`에 **항상** `@Valid`를 붙인다. record에 아직 제약이 없어도 붙여 두어, 나중에 제약을 추가할 때 빠뜨리지 않게 한다.

```java
public ResponseEntity<TripContextResponse> create(
        @CurrentUserId Long userId,
        @Valid @RequestBody CreateTripRequest request) {
    // ...
}
```

- 한 모듈 안에서는 Service가 자기 Request DTO를 받고 Response DTO를 돌려줘도 된다(현재 코드의 방식). 다른 모듈을 호출할 때는 `application` 계층의 타입으로 주고받는다([모듈·의존성](모듈-의존성.md)).
- 잘못된 값이 계약상 **도메인 오류 코드**로 나가야 하는 enum 성격의 요청 필드는 `String`으로 받고 Service에서 검증한다(예: `transport` → `TRIP_INVALID_TRANSPORT`, `scheduleDensity` → `ONBOARDING_INVALID_SCHEDULE_DENSITY`). 그렇지 않은 필드는 enum으로 받아 변환 실패를 `COMMON_INVALID_REQUEST`로 둔다.

엔티티를 API 응답으로 직접 반환하지 않습니다. 비밀번호, 토큰 해시, 내부 상태가 노출되지 않도록 Response DTO에서 외부 공개 필드를 명시합니다. 비밀번호가 포함된 Request를 로그에 남길 때는 값을 마스킹합니다.

이름은 `{동작}{대상}Request`, `{대상}Response` 형식을 사용합니다. 예: `CreateTripRequest`, `UpdateTripContextRequest`, `TripContextResponse`, `MyTripResponse`.

## ID 타입

엔티티 PK, 연관관계 식별자, Service 파라미터, DTO의 내부 ID는 `Long`으로 통일합니다.

```java
TripContextResponse getContext(Long userId, Long tripId);
void leave(Long userId, Long tripId);
```

현재 프로젝트의 JPA PK 구성과 일치하므로 새 기능에서도 `Integer`나 숫자를 담은 `String`을 사용하지 않습니다. 예외는 다음뿐입니다.

- 온보딩 제출 ID: `UUID`
- 지역 ID: 5자리 `SIG_CD` `String`
- 코스 항목 ID(`itemId`): `a-{n}`·`m-{n}` 형식의 `String`
- 외부 시스템이 문자열로 정의한 식별자(카카오 장소 ID, TourAPI contentId 등)

## 엔티티 감사 시각

생성·수정 시각은 클라이언트 입력이나 `LocalDateTime.now()` 필드 초기값으로 채우지 않는다. `JpaAuditingConfig`와 `AuditingEntityListener`가 영속 직전에 서버 시각을 기록한다.

- `created_at`과 `updated_at`을 모두 가진 엔티티는 `shared.persistence.BaseTimeEntity`를 상속한다.
- 생성 시각만 가진 엔티티는 `@CreatedDate`를, 수정 시각만 가진 엔티티는 `@LastModifiedDate`를 기존 컬럼에 붙인다.
- `createdAt`은 `updatable = false`로 유지한다.
- DB 기본값은 외부 적재·직접 SQL 경로의 안전망이고, JPA 경로의 값은 Auditing이 책임진다.
- `TripPlan`, `TripParticipant`는 `BaseTimeEntity`를 상속한다.

## 엔티티 변경

새 코드의 엔티티에는 클래스 수준 `@Setter`를 붙이지 않는다. 상태 변경은 의도를 드러내는 메서드(`changeTransport(...)`, `revoke(...)` 등)로 노출하고, 그 메서드 안에서 도메인 규칙을 검사한다.

이미 병합된 Flyway migration 파일(`V{n}__*.sql`)은 절대 고치지 않는다(체크섬이 바뀌어 기존 DB에서 기동이 실패한다). 스키마 변경은 항상 새 버전 파일로 추가한다.

## 현재 시각

서비스·도메인이 쓰는 "오늘"과 "지금"은 주입된 `java.time.Clock`에서 얻는다(`LocalDate.now(clock)`). `Clock` 빈은 `shared.config.TimeConfig`가 `Asia/Seoul` 기준으로 등록한다. 테스트는 고정 `Clock`을 주입한다.

- 새 코드는 필수다. `LocalDate.now()`·`LocalDateTime.now()`를 인자 없이 호출하지 않는다.
- 기존 코드의 인자 없는 `now()` 호출은 그 코드를 고치는 PR에서 전환한다.

감사 주체(createdBy/updatedBy)는 아직 MVP 범위가 아니다. 추가할 때는 인증 사용자 resolver와 별도 `AuditorAware` 계약을 함께 설계한다.

## 사용자 정보 주입

Controller는 `@CurrentUserId Long userId`로 인증 회원 ID를 받고, Service에는 필요한 `userId`만 전달한다. 이것이 표준이다. JWT principal(`AuthenticatedUserPrincipal`)이 없으면 `AUTH_UNAUTHENTICATED`(401)로 변환된다.

```java
@PostMapping
public ResponseEntity<TripContextResponse> create(
        @CurrentUserId Long userId,
        @Valid @RequestBody CreateTripRequest request) {
    return ResponseEntity.status(HttpStatus.CREATED)
            .body(tripService.createTrip(userId, request));
}
```

ID 말고 다른 인증 정보가 필요할 때만 `@CurrentUser CustomUserDetails user`를 쓴다.

Controller와 Service는 `SecurityContextHolder`를 직접 읽지 않는다. 메서드 시그니처만 보아도 인증 사용자 정보가 필요한지 알 수 있어야 한다.
