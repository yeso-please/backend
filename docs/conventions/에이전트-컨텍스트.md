# 에이전트 컨텍스트

에이전트가 작업을 시작할 때 저장소의 규칙과 현재 상태를 빠르게 파악할 수 있도록 문서의 읽기 순서와 사실의 위치를 고정합니다.

## 읽기 순서

1. `README.md`
2. `docs/conventions/README.md`
3. 작업 대상 도메인의 `docs/features/*.md`
4. 관련 `docs/api/*.md`
5. 관련 `docs/adr/*.md`
6. 실제 코드와 테스트

에이전트는 문서와 코드가 다르면 추측으로 메우지 않고, 작업 명세를 `blocked`로 표시하거나 작업 결과에 차이를 남깁니다.

## 문서가 제공해야 하는 정보

- 현재 상태: 구현 여부와 마지막 갱신일
- 작업 범위와 명시적인 제외 범위
- 입력·출력·에러 계약
- 권한과 데이터 변경 범위
- 완료 기준과 실행할 검증 명령
- 결정된 내용과 아직 결정되지 않은 내용
- 관련 문서와 Issue·PR 링크

## 에이전트 작업 결과

작업 결과는 다음 순서로 기록합니다.

```markdown
## 변경 사항

-

## 검증

- 명령: `./gradlew.bat test`
- 결과: 통과

## 문서 동기화

- 갱신한 API 명세:
- 갱신한 작업 명세:
- 추가·갱신한 ADR:

## 미해결 사항

-
```

에이전트가 생성한 문서도 사람이 리뷰할 수 있어야 합니다. 문서를 코드의 대체물로 사용하지 않고, 코드·테스트·문서가 같은 계약을 표현하도록 유지합니다.
