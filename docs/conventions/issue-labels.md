## 작업 종류 라벨

종류는 주된 목적 하나를 선택한다. 기능 구현에 테스트·문서가 포함된다고 종류를 여러 개 붙이지 않는다.

| 라벨 | 기준 | 색상 |
|---|---|---|
| feat | 새 기능·기능 확장 | 2DA44E |
| bug | 잘못된 동작 수정 | D73A4A |
| infra | 빌드·CI·배포·실행 환경 | 8B5CF6 |
| docs | 문서 자체의 작성·정리 | 0075CA |
| refactor | 동작을 유지하는 코드 구조 개선 | FFA500 |
| chore | 그 외 유지보수·진행 현황 관리 | 6E7781 |

## 영역 라벨

실제로 변경하거나 책임을 다루는 영역 1~2개를 선택한다. 단순히 호출하는 모든 영역을 붙이지 않는다.

| 라벨 | 담당 영역 | 색상 |
|---|---|---|
| area: auth | 계정·로그인·토큰 인증 | C5DEF5 |
| area: profile | 온보딩·여행 성향·취향 임베딩 | C5DEF5 |
| area: attraction | 지역·관광지·식당·공식 코스·콘텐츠 품질 | C5DEF5 |
| area: trip | 여행·참여자·일정 생성/편집/확정·초대/공유 | C5DEF5 |
| area: shared | 공통 오류·인증 주체·웹 설정 | C5DEF5 |
| area: platform | 빌드·CI·RDS·배포 환경 | C5DEF5 |

platform은 작업 분류이며 별도 Java 패키지를 뜻하지 않는다.

전체 구조 문서·진행 현황처럼 전역 작업에는 모든 영역을 나열하지 않아도 된다. 종류·영역 이름을 같은 의미의 동의어로 중복 생성하지 않는다.

## 역할 분리

- 담당자: Assignee
- 진행 상태: Projects의 Todo / In progress / In review / Done
- 출시 목표: Milestone (예: v1.0)
- 우선순위: 필요할 때 Projects의 Priority
- 진행 불가: 필요한 경우 `blocked` (D73A4A)와 원인·선행 이슈 링크. 단순히 나중에 할 작업이라는 이유로 붙이지 않는다.

제목은 기존 `{type}: 한국어 설명`을 유지한다. 버그 수정 제목의 fix와 이슈 라벨 bug는 역할에 맞게 사용한다. WORK별 적용안은 [담당 분배](../mvp/delivery.md)의 구현 위치 표에 있다.

이 문서는 기준만 정의한다. 라벨·Milestone·Projects 생성과 기존 이슈 일괄 적용은 도메인 문서 PR 병합 후 진행한다. 저장소에는 GitHub 기본 라벨(`enhancement`, `documentation` 등)이 남아 있으며, 적용할 때 위 이름으로 정리한다.
