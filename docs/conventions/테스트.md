# 테스트

여러 명이 동시에 통합 테스트를 추가해도 복붙·context 폭증·데이터 충돌이 없도록 정한 팀 규칙이다. 공용 기반 코드는 `src/test/java/com/yeso/backend/support/`에 있다.

## 종류

| 종류 | 이름 | 목적 | Docker |
|---|---|---|---|
| 단위 테스트 | `*Test` | DB·Spring 없이 도메인·서비스·어댑터 로직 검증 | 불필요 |
| 통합 테스트 | `*IntegrationTest` | API·Security·DB를 포함한 흐름을 MockMvc로 검증 | 필요 |
| 구조 테스트 | `ArchitectureTest` | [모듈-의존성.md](모듈-의존성.md) 규칙을 ArchUnit으로 검증 | 불필요 |

## 엔드포인트 PR 최소 테스트

엔드포인트를 추가·변경하는 PR은 해당 엔드포인트에 대해 아래를 갖춘다.

- 성공 1건 — 상태 코드와 [docs/api](../api)에 적힌 응답 계약 필드를 `jsonPath`로 확인한다.
- 토큰 없이 호출하면 `401 AUTH_UNAUTHENTICATED`(공개 API 제외).
- 참여자가 아닌 사용자·없는 ID면 404(존재를 숨기는 계약이면 둘 다 같은 code).
- Bean Validation 실패면 `400 COMMON_INVALID_REQUEST`와 `fieldErrors[].field`.
- docs/api에 적힌 오류 code마다 1건 — 반드시 `$.code`를 검증한다(상태 코드만 보지 않는다).
- 계약에 경계값이 있으면 안/밖 한 쌍. 예: `nights` 0·6 허용, -1·7 거부. 만료 7일이면 7일 1초 전 유효, 7일째 만료.
- 동시성을 약속하는 API(중복 생성 차단·낙관적 잠금·토큰 회전 등)만 동시성 1건.

## 공용 기반

통합 테스트는 반드시 `IntegrationTest`를 상속한다. 설정이 한 곳에 있어서 전체 실행에서 Spring context와 PostgreSQL 컨테이너가 **하나만** 뜬다.

| 클래스 | 역할 |
|---|---|
| `IntegrationTest` | `@SpringBootTest`·MockMvc·`test` profile. `mockMvc`, `jsonMapper`, `fixtures`, `clock`, `fakeEmbeddingClient`를 준다. 매 테스트 후 DB 정리·fake·시계 초기화 |
| `TestInfraConfig` | 공유 컨테이너(`postgres:17-alpine`), `@Primary` fake client, `@Primary MutableClock` |
| `ApiFixtures` | 가입·설문·여행 생성·초대·공유 링크 등 준비 동작. 실제 API를 호출하고, 이메일은 카운터로 매번 고유하다 |
| `DatabaseCleaner` | 앱 스키마 전체 `TRUNCATE ... RESTART IDENTITY CASCADE`(`flyway_schema_history` 제외) |
| `MutableClock` | 고정 시각 시계. `today()`·`now()`·`setTo()`·`advance()`·`reset()` |
| `src/test/resources/application-test.yml` | `jwt.secret`, 임베딩 재시도 sweeper 끄기 등 테스트 설정 |

금지 사항 — 어기면 context 캐시가 갈라져 컨테이너·context가 늘어난다.

- 테스트 클래스에 컨테이너, `@TestPropertySource`, `@Import`, `@MockitoBean`, `@DirtiesContext`를 붙이지 않는다. 설정이 필요하면 `application-test.yml`에, 새 fake는 `TestInfraConfig`에만 추가한다.
- 여러 테스트가 쓰는 준비 동작은 `ApiFixtures`에만 둔다. 다른 테스트 클래스의 static 메서드를 참조하지 않는다.
- 준비는 API로 한다. 저장소로 엔티티 필드를 바꿔 상태를 만들지 않는다(날짜·만료는 시계로 만든다).
- 요청 JSON은 text block(`"""`)으로 쓴다.

```java
class DiaryIntegrationTest extends IntegrationTest {

    @Nested
    @DisplayName("일기 작성")
    class Create {

        @Test
        @DisplayName("참여한 여행이면 201과 일기 id를 반환한다")
        void create_success() throws Exception {
            ApiFixtures.Member me = fixtures.onboardedMember();
            Long tripId = fixtures.createTrip(me.accessToken(), clock.today().plusDays(5), 1);

            mockMvc.perform(post("/api/trips/{tripId}/diaries", tripId)
                            .header("Authorization", me.bearer())
                            .contentType(MediaType.APPLICATION_JSON)
                            .content("""
                                    {"content":"좋았다"}
                                    """))
                    .andExpect(status().isCreated())
                    .andExpect(jsonPath("$.id").isNotEmpty());
        }

        @Test
        @DisplayName("토큰이 없으면 401 AUTH_UNAUTHENTICATED다")
        void create_withoutToken_returnsUnauthorized() throws Exception {
            mockMvc.perform(post("/api/trips/{tripId}/diaries", 1)
                            .contentType(MediaType.APPLICATION_JSON)
                            .content("{}"))
                    .andExpect(status().isUnauthorized())
                    .andExpect(jsonPath("$.code").value("AUTH_UNAUTHENTICATED"));
        }
    }
}
```

## 데이터 격리

- 매 테스트 후 `IntegrationTest`가 모든 테이블을 TRUNCATE CASCADE한다. 테스트는 빈 DB에서 시작한다고 가정해도 된다. 참조 데이터(예: 지역)가 필요하면 그 테스트의 `@BeforeEach`에서 넣는다.
- 클래스·테스트에 `@Transactional` 롤백을 쓰지 않는다. 롤백되는 트랜잭션에서는 `AFTER_COMMIT` 리스너(설문 제출 후 임베딩 등)가 돌지 않고, 동시성 테스트의 다른 스레드는 커밋되지 않은 데이터를 보지 못해 실제와 다르게 동작한다.
- 전역 count(`repository.count()`)로 단정하지 않는다. 내 사용자·내 여행 범위의 API 응답으로 확인한다.

## 시간

- 서비스는 주입받은 `Clock`으로 `LocalDate.now(clock)`·`LocalDateTime.now(clock)`을 쓴다(`shared/config/TimeConfig`, Asia/Seoul). 현재 trip 모듈이 적용돼 있고, 다른 모듈은 해당 코드를 손볼 때 옮긴다.
- 통합 테스트의 시계(`MutableClock`)는 **2026-10-01 10:00 Asia/Seoul**에 고정이다. 날짜는 `clock.today().plusDays(n)`처럼 이 값에서 상대적으로 만든다.
- 만료·종료는 시계를 돌려 검증한다. 예: 여행 종료 → `clock.setTo(endDate.plusDays(1))`, 초대 만료 → `clock.advance(Duration.ofDays(7))`.
- 테스트 코드에서 `LocalDate.now()`·`LocalDateTime.now()`·`Thread.sleep`을 쓰지 않는다.
- 단위 테스트는 `LocalDate.of(2026, 10, 1)` 같은 고정값을 쓴다.
- JPA auditing(`createdAt`·`updatedAt`)과 JWT 만료는 아직 시스템 시계다 — 시계를 돌려도 access 토큰은 만료되지 않는다.

## 외부 API

- 외부 호출은 `XxxClient` 인터페이스 뒤에 둔다. 통합 테스트는 `TestInfraConfig`의 `Fake*Client`(`@Primary`)를 쓰고, 테스트가 `setMode(...)`로 성공·일시 장애·영구 실패를 고른다. 예: `FakeEmbeddingClient`.
- `IntegrationTest`가 매 테스트 후 fake를 `reset()`한다. 새 fake도 `reset()`을 두고 `IntegrationTest.resetSharedState()`에 추가한다.
- 테스트에서 실제 네트워크를 호출하지 않는다. HTTP 계층(상태 코드·타임아웃 매핑)은 JDK `HttpServer`로 단위 테스트한다. 예: `HttpEmbeddingClientTest`.

## 예외

`PostgresqlFoundationIntegrationTest`만 전용 컨테이너를 쓴다. `flyway.clean()`으로 스키마를 지우고 migration을 다시 올리는 테스트가 있어서 공유 컨테이너를 쓰면 다른 테스트의 스키마가 깨진다. migration 검증 외에는 이 형태를 따라 하지 않는다.

## 실행

- Docker가 필요하다. Docker가 없으면 통합 테스트는 건너뛰지 않고 실패한다.
- 전체: `./gradlew test`
- 부분: `./gradlew test --tests "com.yeso.backend.trip.*"`, `./gradlew test --tests "*TripIntegrationTest\$Create"`
- PR 전 로컬에서 전체 통과를 확인하고, CI가 녹색이어야 머지한다.

## 이름

- 메서드: `{대상}_{시나리오}` 형식 영어. 예: `create_overlapsExistingTrip_returnsConflict`.
- `@DisplayName`은 필수이고 한국어로 "조건이면 결과" 형태로 쓴다. 예: "이미 만든 여행과 겹치면 409와 conflicts를 반환한다".
- 통합 테스트는 엔드포인트(기능)별로 `@Nested` 클래스로 묶고 `@DisplayName`을 붙인다.
