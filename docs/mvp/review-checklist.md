# MVP 빠른 리뷰 체크리스트

제품 결정은 [decisions.md](decisions.md)에 확정되어 있다. 팀 리뷰는 취향 재토론이 아니라 구현 불가능, 보안, 데이터 손실, API 모순을 찾는 데 집중한다.

## 계약 확인

- [ ] 로컬 이메일 로그인/JWT·refresh cookie 계약이 프론트와 맞는다.
- [ ] 데모 12문항·태그·제외·좋았던 여행지와 프로필 재검사 구조가 재사용 가능하다.
- [ ] 0~6박, endDate 서버 계산, 캘린더 disabled와 서버 409 날짜 중복 차단이 모든 API에서 같다.
- [ ] 카카오톡 공유는 사용자 선택 공유 UI이며 서버 직접 발송이 아님을 이해했다.
- [ ] 최초 일정은 회원만 생성하고, 손님은 비회원 온보딩 후 기본 VIEW이며 소유자만 EDIT 권한을 부여한다.
- [ ] FULL_RANDOM/CONDITIONAL 체크 항목과 리롤 동일 지역 허용이 프론트 UX와 맞는다.
- [ ] 여행 일수별 후보 기준과 소개/이미지/설명 누락 지역 제외가 데이터 규모에서 가능한지 측정 계획이 있다.
- [ ] 첫날 12:00/마지막 날 17:00/당일 12:00~20:00과 RELAXED 4/PACKED 6 상한을 UI가 가정으로 표시한다.
- [ ] 지도 핀의 이름·썸네일·상세·추가 동작과 ADD 후 전체 일정 재검사가 프론트 계약과 맞는다.
- [ ] TourAPI 39 우선 식당, 공공 지정 근거 label, 카카오 fallback이 구분되고 없는 메뉴·평점·인기를 만들지 않는다.
- [ ] Python 장애의 공식 코스→규칙 코스 폴백과 LLM 제목 폴백이 동작 가능하다.
- [ ] 공유 token, 비밀번호, 외부 키, 자유서술 로그 금지가 구현에 반영된다.
- [ ] Flyway가 유일한 schema 변경 경로이며 Hibernate auto-update와 운영 자동 mutation이 없다.

## 구현 전 측정

- [ ] 1~7일 각각의 적격 지역 수
- [ ] 지역별 설명+이미지+좌표 교집합과 `SOURCE_EMPTY` 목록
- [ ] TourAPI 공식 코스의 지역/관광지 매핑률
- [ ] 카카오 Local 예상 호출량과 장애 시 UI
- [ ] TourAPI 음식점·농가맛집·모범/향토음식점·착한가격업소의 SIG_CD별 실제 커버리지와 중복률
- [ ] 임베딩 후보 계산 지연시간과 pgvector 필요 여부

## 유일한 미결정

- [ ] 외부 길찾기 실패 때 확정을 막을지, 근사 경고로 저장할지 결정한다. 결정 전에는 모든 이동 시간을 `estimated`로 표시한다.
