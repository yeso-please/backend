# MVP 팀 리뷰 체크리스트

상태: **리뷰용**. [구현 작업서](implementation-workpack.md)와 함께 세 명이 먼저 검토한다. 각 항목에 `승인/수정/보류`, 담당자, 결정 날짜를 PR 코멘트 또는 ADR에 남긴다. 보류가 P0이면 관련 구현을 시작하지 않는다.

## P0 — 구현 계약을 바꾸는 결정

- [ ] MVP 인증은 카카오만이며 이메일/구글/게스트는 제외한다. 카카오 redirect URI 허용 목록과 JWT 전달/갱신/로그아웃 방식을 확정한다.
- [ ] 날짜는 추첨 전에 필수이며 `CONFIRMED` 여행의 하루라도 겹침을 차단한다. 날짜 범위/최대 여행 일수와 동시 확정 잠금 방식을 정한다.
- [ ] 250 지역 모두 지도에 보이지만 추첨은 추천 가능 지역만 대상으로 한다. 적격 지역 판정과 후보 부족 응답을 승인한다.
- [ ] `FULL_RANDOM`의 균등 추첨, 조건 기반 확률 추첨, 리롤 제외 범위/소진 시 완화를 승인한다.
- [ ] 지역 카드는 별도 검수 콘텐츠+출처 또는 명시적 폴백을 사용한다. TourAPI 관광지 설명을 지역 공식 설명으로 표시하지 않는다.
- [ ] 이미지 없는 관광지는 추천 제외한다. URL 존재와 검증 완료를 구별하고, 설명 없는 관광지 허용 여부를 확정한다.
- [ ] 첫날 **지역 도착**/마지막 날 **지역 출발** 시각은 지역 선택 뒤 받으며 미정 허용. 프리셋·미정 기본 가정·`estimated` 표기를 확정한다.
- [ ] 식사 시간은 자동 배치, 식당 자동 지정은 제외한다. 지역 음식 제안은 검수된 데이터가 있는 곳만 후속 적용한다.
- [ ] Python은 같은 모델/버전의 임베딩만 생성한다. Spring이 후보 점수와 코스 조립을 소유한다. 배포 위치와 장애 폴백을 정한다.
- [ ] PostgreSQL/Flyway 스키마, `SIG_CD` 문자열, 원천 콘텐츠 ID, 날짜별 방문지, 임베딩 버전/차원, 이미지 품질 필드를 승인한다.
- [ ] 초안은 DB에 저장하지 않고 확정 시 재검증한다. 초안 재시도/리롤/확정의 멱등성 및 길찾기 장애 처리를 정한다.
- [ ] `api.md`의 요청/응답/상태 코드 예시를 프론트가 승인한다. 구형 문서와의 우선순위를 명시한다.

## P1 — 출시 품질 게이트

- [ ] 지원 여행 일수별 지역당 최소 관광지 후보·리롤 여유를 데이터 분포로 산출한다.
- [ ] 운영시간 불명, 이동시간 근사, 비자동차 이동의 정확도 경고 표기를 승인한다.
- [ ] 데이터 이관 전후 지역별 건수·좌표·이미지·설명·임베딩 검증 리포트 양식을 승인한다.
- [ ] 개발 RDS 연결·백업/복구 리허설, Python 장애, TourAPI/길찾기 장애 테스트 담당자를 정한다.
