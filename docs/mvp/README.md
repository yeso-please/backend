# TriPin MVP 설계 기준

상태: **제품 결정 반영 완료 / 구현 전** (2026-09-20). 이 폴더가 MVP 구현의 우선 기준이다. 코드와 충돌하면 임의 구현하지 말고 문서를 먼저 고친다.

## 구현할 사용자 흐름

```text
로컬 회원가입·로그인 → 최초 온보딩(여행 성향·일정 밀도) → 시작일·몇 박 선택
→ 캘린더에서 기존 확정 여행 날짜 제외 → 완전 랜덤 또는 조건 체크 추첨 → 지역 카드
→ 도착/출발 시각 입력 → 개인+초대 친구 성향 코스 생성
→ 지도에서 관광지 조회·교체·직접 추가 → 지역 음식·식당 검색/추가
→ 확정 저장 → 조회/수정 권한별 공유 링크
```

## 고정된 기술 경계

| 영역 | MVP 결정 |
|---|---|
| 인증 | 이메일·비밀번호 로컬 로그인, JWT access/refresh. 카카오 로그인 제외 |
| 초대 | 서버 자동 카카오 메시지가 아니라 카카오톡 공유 UI로 초대 링크 전송 |
| 일정 충돌 | 확정 여행과 겹치는 날짜는 캘린더에서 비활성화하고 서버에서도 생성·변경·확정을 차단 |
| DB | PostgreSQL + Flyway. 로컬/Testcontainers 검증 후 개발 RDS 적용 |
| 관광지 | 동일 지역이며 좌표·설명·검증된 이미지가 모두 있는 장소만 추천 |
| 개인화 | Python은 임베딩 생성, Spring은 점수·제약·일정 조립 |
| 장애 폴백 | 취향 임베딩 장애 시 적재된 TourAPI 공식 코스, 없으면 비개인화 규칙 코스 |
| 식당 | TourAPI 음식점(39)과 출처가 명확한 공공 지정 데이터를 우선 제안하고, 부족하면 카카오 Local 검색을 사용자가 선택. 근거 없는 맛집·인기·대표 메뉴 주장은 금지 |
| 제목 | 일정 확정 뒤 LLM이 감성 제목만 생성. 실패하면 규칙 기반 제목 |

## 기존 문서와의 관계

`docs/FEATURE-SPEC.md`, `docs/API-DESIGN-DRAFT.md`, `docs/BUTTON-SPEC.md`는 데모 분석 기록이다. 카카오 로그인, 게스트 우선, SQLite, 날짜 중복 허용 등 현재 결정과 충돌하는 내용은 구현 근거로 쓰지 않는다. 데모 저장소는 데이터와 알고리즘 아이디어만 읽기 전용으로 참고한다.

## 구현 완료의 의미

문서 작성만으로 완료가 아니다. 각 기능은 Flyway migration, Controller/Service/Repository, 실패 경로 통합 테스트, `docs/features/`, `docs/api/`가 같은 PR에서 일치해야 한다. 운영 RDS 변경과 외부 메시지 전송은 문서나 에이전트 프롬프트만으로 자동 승인되지 않는다.
